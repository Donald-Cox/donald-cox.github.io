System 1

Dock intake

A pallet arrives with dozens of cases, and each batch has to reach the storefront and the accounting system with its own traceable record. That used to mean clipboards and retyping lot codes by hand.

How it works

  • Four chained workflows behind one phone app
  • A vision model reads labels, and the printed packing list stays ground truth
  • Paperwork, side count and close-up count are compared, and a person settles any disagreement before anything books

System 2

Inventory sync and reorder routing

The production plan runs on a workbook of about 1,000 active parts. Someone used to export a report, upload it and update dates by hand each morning. Now it runs itself.

How it works

  • Pulls stock live from a desktop accounting system, through an API bridge
  • Three scheduled runs a day, plus an hourly poll for manual requests
  • Keeps automation out of the columns people own, so a person's reassignment sticks
  • Sets reorder dates and routes each part to its work station
3×a day, up from once at best
63 to 83hours a year returned, estimated

Run the inventory demo

System 3

Rack-to-receipt production ledger

A stock rack that existed in no system is now tracked part by part, from raw blank to accounting receipt, across stations, travelers and labels. Its assistant can plan any floor action and cannot commit one.

How it works

  • Each button press is planned in plain words, and the server enforces a person's Yes
  • Single-use tokens, tied to the login, refused if a part moved since the plan
  • Move and event logs are append only, enforced by the database
  • Assistant evals gate each deploy: 13 cases, 5 of them safety cases that must all pass
487tests passing on version 2.0
78 of 78real floor presses matched in shadow, over 4 days

Run the ledger demo

System 4

Shipping verification kiosk

Two camera stations check packed orders before they ship. A vision model reads what is in the box, and code compares it with the order system. The model never makes the decision.

How it works

  • One workflow of 72 steps across 5 webhooks
  • Not told the quantity or slip number, so it can't simply confirm them
  • Schema-checked answers, then confidence floors by product type
  • 9 conditions force a hold, and more than a dozen send an order to review
  • Photos of each order stay on file as the dispute record
17wrong boxes stopped and fixed in 12 weeks, a measured floor
~9 sa verify, on one partial day of the current build

System 5

Operations watcher

A read-only console over everything. It looks for the failure dashboards miss: the system said something was wrong, and the work moved on anyway.

How it works

  • Scans every 5 minutes during working hours, for known failure classes
  • Reads through a read-only collector and keeps its findings in its own store
  • Each rule records the real incident that created it
5 minbetween scans, on weekdays
0 writesto any system it watches

How I ship

Each verdict engine and prompt change is tested against written gates before it reaches the floor.

The release process is a system too. Gates are written before the run and don't change after it, and a person rules on any gate a change fails. Verdict engine changes replay against stored decisions, and prompt changes run side by side against the live prompt.
